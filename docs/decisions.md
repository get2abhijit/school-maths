# Decisions

| # | Decision | Alternatives | Why |
|---|---|---|---|
| D1 | Engine source in `src/*.js` (CommonJS), bundled by `tools/bundle-engine.js` into a single UMD `engine.js` (`window.MathEngine` in browser) | One hand-maintained engine.js; ES modules | Small, testable modules; one shippable file; no npm. A test fails if engine.js is out of date |
| D2 | PRNG mulberry32, child seeds via FNV-1a of `"seed:k"` | xorshift, sfc32 | Tiny, well known, reproducible; golden test pins output |
| D3 | Exact `Fraction` (BigInt) for all answers; rounding half away from zero, explicit `places` | Decimal library; floats | No dependency, no float error (e.g. 1.005 → 1,01) |
| D4 | Two number parsers: strict machine parser (`Fraction.of`, dot only) and student parser (`parseNumber`: comma or dot, fractions, mixed numbers) | One parser | Student input needs lenience; stored data must be unambiguous |
| D5 | `1.000` (dot + exactly 3 digits after a non-zero integer part) is **invalid input** (`ambiguous_separator`), not a number | Treat as 1 or as 1000 | German students may write thousands separators; asking is safer than guessing |
| D6 | Hand-written recursive-descent parser; implicit multiplication before variables and `(`; `x2` rejected; `1/2x` = (1/2)·x; `-x^2` = −(x²); `:` = division | eval; permissive grammar | Safe and predictable; school notation; ambiguous forms rejected with a message |
| D7 | Equivalence = exact evaluation at ≥8 of 16 fixed rational test points **and** polynomial normal-form comparison when both sides are polynomials (normal form decides) | Sampling only; CAS | Normal form is definitive for Grade 7 algebra; sampling covers rational terms |
| D8 | Different domains (one side undefined at a test point, the other defined) ⇒ not equivalent | Ignore such points | Conservative; irrelevant for Grade 7 polynomials |
| D9 | "Equivalent but wrong form" returns `status: 'incorrect'` with `equivalent: true` and a specific code | Separate status `partial` | Keeps three statuses (correct/incorrect/invalid); UI can still say "richtig umgeformt, aber noch nicht fertig" |
| D10 | Form `expanded` = sum of monomials, each monomial once, ≤1 numeric factor on top and below, no x·x, no zero terms, no unreduced literal fraction | Compare to canonical string | Accepts any order and both `x/2` and `1/2x` |
| D11 | Text fields are strings with `$…$` inline LaTeX | Structured segment arrays | Simple to author; one renderer (KaTeX) in practice and print |
| D12 | Exactly 5 hints in fixed order: orientation, strategy, step, solution, alternative | Variable count | Uniform UI; enforced by `validateQuestion` |
| D13 | Pipeline: sample → constraints → build → **independent** `solve` must be accepted by the built answer spec → `validateQuestion` (incl. every distractor must be rejected) → publish; up to 100 derived seeds | Trust the builder | Guarantees no unvalidated or ambiguous question is published |
| D14 | Question id `templateId@version/Llevel/seed` (requested seed); signature = FNV-1a of `templateId|level|canonical params` | Hash everything | Id regenerates content; signature detects effective duplicates across seeds |
| D15 | Catalog: Grade 7 = textbook sections; curriculum mapping per skill with `status` | Map the whole 7/8 band | Avoids techniques beyond what the student has met; verifying S4/S5 later only flips statuses |
| D16 | One template per family group; id `<skillId>.<group>`; all templates registered in `src/templates/index.js` | One template per skill; one per family | Families with the same answer logic share code; levels stay comparable; registry is the single list the UI and tests use |
| D17 | Task terms are displayed via `toLatex(parse(machine))`, never hand-written LaTeX | Separate display strings | What the student sees and what the solver computes come from the same parse and cannot drift |
| D18 | Each template's `solve` takes a different path from `build`: build = direct arithmetic on parameters; solve = polynomial normal form, `evaluate`, line-by-line equivalence or brute-force search | Re-using build's value | Catches arithmetic and construction errors; the path is documented in each template's docstring |
| D19 | Optional `signatureParams(params)` per template: signatures ignore presentation-only randomness (option order, chosen distractor options) | Hash all params | Otherwise two effectively identical questions get different signatures and both appear in one session |
| D20 | LaTeX printer: non-leading negatives and negations are bracketed; numbers typed with a separator print as decimals with `{,}`; `explicitMul` prints `·` before brackets in substitutions | Always bracket; never bracket | School notation (`5+(−3)·4`, `3·(−2)`, `0,5x`) without double signs |
| D21 | Form `factored_complete` = one bracketed simplified sum times monomial factor(s); inner coefficients integral with gcd 1 and no common variable. Sign choice free: −3(2x−3) and 3(−2x+3) both correct | Require positive outer factor | Both are mathematically complete; the book convention could not be verified |
| D22 | x·x (`term_times_term`) and sum × sum are not generated; figures are described in words until the geometry session adds SVG | Generate them anyway | Scope is flagged provisional in the catalog; no techniques beyond the verified curriculum |
| D23 | Machine decimals with exactly three places get a trailing zero (`1.1250`) | Relax D5 for machine strings | Keeps one tokenizer and the D5 guard for students |
| D24 | Golden snapshot (`test/golden/ch1.golden.json`) records id, signature, prompt, promptLines, canonical answer and result for 3 seeds × every template/level; regenerate with `node tools/update-golden.js`. After the first release, any content change also requires a template version bump | Snapshot whole question objects | Pins what students see without making hint wording changes painful; versioning keeps stored seeds meaningful |
| D25 | "Terme aufstellen" accepts any equivalent term (form `any`); simplification tasks demand `expanded` or `factored_complete` | Demand the simplest form everywhere | Setting up a term is the skill being practised there, not simplifying it |
| D26 | Optional Question field `promptLines: [string]` for block content under the prompt (e.g. a calculation to check) | HTML in prompt | Keeps text fields plain strings with `$…$`; UI and print render lines as a block |
| D27 | Session and progress logic live in the engine (`src/practice.js`, `src/progress.js`) as pure functions over JSON objects; the UI only stores them and renders | State machine in the UI | Testable in Node; keeps "no answer/curriculum logic in the UI"; enforced by `test/build.test.js` (UI must not touch solutions, distractors, catalog ids) |
| D28 | KaTeX 0.16.22 from cdnjs with `output: 'mathml'`, no KaTeX CSS or fonts; plain-text fallback (`texToText`) when KaTeX is unavailable; late-loading KaTeX upgrades already-rendered formulas | KaTeX HTML output with its CSS; inlining KaTeX | The Artifact CSP allows scripts from cdnjs but no external stylesheets; MathML needs neither; fallback keeps the app usable offline. 0.16.22 is > 1 year old (supply-chain rule). No SRI hash: it could not be verified against the cdnjs file from the sandbox (no access to cdnjs), and a wrong hash would silently disable formulas |
| D29 | System fonts only | Google Fonts | Loading Google Fonts sends the IP to Google (DSGVO issue in Germany); system fonts are legible and offline |
| D30 | Routes are plain hash tokens (`#start`, `#kapitel`, `#ueben`, `#arbeitsblaetter`, `#wiederholen`, `#fortschritt`) | `#/path` routes | The Artifact viewer only forwards plain `#token` hashes |
| D31 | "Automatisch" = deterministic difficulty ramp per session (`autoLevels`), labelled "Gemischt, steigend" | Adaptive level choice now | Adaptive rules belong to a later session and need documented, tested parameters; a ramp is honest and predictable |
| D32 | "Neue Zahlen" replaces the current item with a fresh instance of the **same template and level** (new signature, deterministic from the session seed); the replaced item stays in the session for statistics but does not count as a question | Same template, any level; retry same numbers only | Lets the student retry the same kind of task with new values; keeps the session length fixed |
| D33 | Invalid input is never stored as an attempt and shows an amber "?" with the parser message plus "Das zählt nicht als Fehler"; wrong = red "✗", right = green "✓" — always symbol + text, never colour alone | One "wrong" state | Requirement: distinguish invalid from wrong; accessibility |
| D34 | Progress import replaces (after confirmation) instead of merging | Merge per skill | Merging counters from two devices double-counts; replace is predictable. Revisit if needed |
| D35 | Export uses the Artifact `downloads` capability when present, else a Blob download, and always offers "Als Text anzeigen" | Blob only | Plain downloads are inert inside published Artifacts; the text path works everywhere |
| D36 | Optional dev dependencies (`jsdom@24.1.3`, `katex@0.16.22`, installed with `npm i --no-save`) power `test/ui.dom.test.js` and `test/katex.test.js`; both files skip cleanly without them | Require them; no DOM tests | `npm test` stays dependency-free; with them, the built page is driven end-to-end in a simulated DOM and every formula is checked against the pinned KaTeX |
| D37 | Focus after "Prüfen": correct → "Nächste Aufgabe" (aria-describedby = feedback); wrong/invalid in a text field → back into the field (aria-describedby includes the feedback); otherwise the feedback block | Always focus feedback | Fast keyboard flow (Enter, Enter) and the feedback is still announced |
| D38 | Worksheet level mix = the selected levels as an ascending ramp over the sheet (easy first); skills alternate round-robin in a seeded order | Random level per question; grouped by skill | Predictable difficulty on paper, mixed topics like a class test; deterministic from the seed |
| D39 | If no selected skill has a slot's level, the next skill's nearest level is used and the item is flagged `levelAdjusted` (lower level wins ties). With today's Ch1 data this never happens; tested with an injected level lookup | Refuse the sheet; silently drop the slot | Later chapters may lack L4; the sheet keeps its length and the flag makes the substitution visible |
| D40 | A stored worksheet = settings + seed + `{qid, signature}` per item + code (hash of spec and qids). `loadWorksheet` regenerates from the qids and refuses on a version or signature mismatch | Store only settings + seed | Only the qids pin template versions; a reprinted key must never silently differ from the sheet on the student's desk |
| D41 | Answer key built in the engine (`worksheetLayout`): choice/multiselect → printed letter(s) + text; table → one value per cell from the cell spec (`numTex`/`toLatex`); others → the template's `solution.result`; "Mit Lösungsweg" adds `solution.steps` and repeats the prompt. Tests convert the printed key text back to input on the test side and require the engine's validator to accept it | Print `canonical` input strings; build the key in the UI | One source of truth; the UI renders only engine output (logic separation test); the round-trip proves the key matches each instance |
| D42 | Page numbers via CSS `@page` margin boxes in a separate `<style id="page-css">` (ui/print-page.css); `size: A4` and margins stay in the main stylesheet. The jsdom test harness ignores exactly that one parse error | Margin boxes in styles.css; JS-generated page numbers | Margin boxes work in Chromium ≥ 131 and are simply ignored elsewhere; isolation guarantees a rejecting parser can never drop the app stylesheet. JS cannot know the browser's page breaks |
| D43 | Printing = select the paper, then `window.print()` (only the visible paper prints). Fallback "Als HTML-Datei speichern": the rendered paper plus the worksheet CSS block (marked `@worksheet-css-start/end`, no theme variables) as a standalone file without scripts | Server PDF; a PDF library | No network, no dependency; `window.print()` may be blocked inside the Artifact frame, the standalone file prints from any browser. Honest UI note: this is browser print, not a generated PDF |
| D44 | Worksheet paper is always black on white with mm/pt sizes, also in dark mode. The calculation space is karriert like the students' exercise books (5-mm squares), drawn as inline SVG: user unit = 1 mm, one `<path>` of plain horizontal/vertical lines every 5 mm, stroke as attributes; no `<pattern>`/`url(#id)` and no CSS background (revised twice on 2026-10-27 after user feedback; see D46) | CSS gradient background with `print-color-adjust: exact` (first S4 version); ruled lines | Students work in kariert books; browsers omit backgrounds when printing unless "Hintergrundgrafiken" is on, so a background grid printed blank. SVG is foreground and always prints, also in the standalone HTML export |
| D45 | Name and date are printed as empty lines; the app never asks for them. The title field warns not to enter a name | Typed name, not stored | Keeps personal data of a minor out of the app entirely |
| D46 | Grid fix after the first Karo version showed blank boxes on the user's screen: removed SVG `<pattern>` + `fill="url(#id)"`; lines are explicit path segments | Keep the pattern and debug; `<base>` workarounds | `url(#id)` references are fragile in embedded/sandboxed pages (suspected cause here; not reproducible without a browser). Plain path lines have no references. Test now verifies the line geometry (every 5 mm, full width and height) |
| D47 | New answer type `solution_set` `{kind: one|none|all, value?}`. UI sends `{kind, value}`; the engine also accepts text (“x = 3”, “L = {3}”, “keine”, “L = {}”, “∅”, “unendlich viele”, “alle”, “ℚ”). No choice or no value → `invalid`; wrong kind → `incorrect` with a kind-specific engine message (e.g. 0 = 0 is not “keine Lösung”). Paper: three boxes, the first with “x = ____” | Three-option `choice` plus a separate number field; free text “L = {…}” only | One validator keeps invalid/wrong apart and gives one canonical object for practice, print and key. Whether LS7 writes solution sets as “L = {…}” was not verified, so the UI uses words and the set notation is merely accepted |
| D48 | Numeric specs may carry `variable` (e.g. `x`, `a`): input “x = 3” is accepted as 3; practice and paper show a “x =” prefix | Reject “x = 3” as invalid | Students naturally write the variable; the prefix makes clear what is asked |
| D49 | Chapter IV word problems use perimeters, ages, sharing and number riddles only; angle contexts (Nebenwinkel, Winkelsumme) are left out until Chapter V is implemented | Include angle equations now | LS7 teaches the angle theorems in V.1–V.2, after IV; no technique before it is taught |
| D50 | Ch IV keeps the catalog's four skills (IV.2 and IV.3 merged). Families added: `spot_error`, `choose_parameter`, `justify_count`, `check_interpretation`. Equations with x² or a product appear only in IV.1 “Lösungen finden” (L4, substitution among given numbers), never to be solved algebraically | One skill per section; quadratic equations | Matches the TOC without going beyond Grade 7 (quadratic solving and Bruchgleichungen are Kl. 9/10) |
| D51 | “Gleichung aufstellen” from a number riddle is multiple choice with misconception equations (missing/extra bracket, wrong operation word, wrong order). Independent check: the riddle's number, computed from the narrative, satisfies exactly one option | Free equation input checked by equivalence | Any linear equation with the same solution is equivalent (even “x = 5”), so a free input cannot tell “set up” from “already solved” |
| D52 | Golden files per chapter (`test/golden/ch1.golden.json`, `ch4.golden.json`); the worksheet golden specs pin their chapter's skills; a test checks every template is covered by some golden file | One file for all templates | Adding a chapter must not rewrite earlier goldens. Verified on 2026-10-27: all 123 Ch1 golden questions and both earlier golden worksheets are unchanged |
| D53 | Worked solutions of linear equations: fixed order (brackets → collect → clear denominators → x-terms to the left → numbers to the right → divide), the operation written right of the line as “│ −5”, term transformations named in words (“Klammern auflösen”, “zusammenfassen”), then a Probe in the original equation | Keep the x-coefficient positive by choosing the side; free order | Deterministic and readable; the alternative hint mentions the other route. Notation not checked against the book (status provisional) |
| D54 | The UI's plain-text formula fallback maps `\qquad \big|` to a spaced bar | Avoid the notation | Keeps worked lines readable when KaTeX cannot be loaded |
| D55 | Money and rounding (Ch6): cents, kaufmännisch (half away from zero). Where a task requires rounding, the prompt says so and the tolerance is half a unit of the last place (0,005 € / 0,05 %), so the exact value is accepted and the neighbouring rounded values are not. Interest over several years is rounded to cents each year; an instance is published only if rounding only at the end gives the same values to within half a cent in every row | Strict per-year rounding only; accept ±1 cent | Both ways of working are taught; no student is marked wrong for a legitimate rounding path, and a cut-off value (4,63 instead of 4,64) is still detected as `rounding` |
| D56 | Numeric specs may carry `unit` (€, %, kg, g, km, m, l, ml, Jahre). Input may carry that unit (also „€ 4,50“, „Euro“, „Prozent“); another known unit → incorrect, `unit_confusion`, with feedback whether the number itself was right; an unknown word stays invalid. Specs without `unit` keep the old strict behaviour | Strip any unit everywhere; “ohne Einheit” instructions as in Ch4 | Students naturally type units in Prozent- und Zinsrechnung; a wrong unit is a real error worth naming. Ch1/Ch4 output and grading unchanged (golden check) |
| D57 | Tables may carry a 2-D `grid` (columns, given text entries, input cells; every cell exactly once). Same per-cell grading. Rendered as a grid in practice, on the student sheet (blank cells) and in the key (filled grid). Cells in the grid are labelled with `aria-label` from the cell label | One long row of inputs; a new answer type | Zinseszins and Tilgungsplan are tables in the book’s sense; data-only extension, no skill-specific UI |
| D58 | Money is displayed without thousands separators (18500 €); input rule unchanged (no thousands point, D5) | „18.500 €“ | Display and the accepted input stay the same form; amounts stay below 100 000 € |
| D59 | Worksheet skill limit raised from 12 to 40 | Keep 12 | With Ch6 there are 14 practicable skills; a mixed revision sheet over all chapters must stay possible |
| D60 | Ch6 models: compound interest year by year (growth factor per year allowed, no closed formula K·qⁿ); loans with a fixed yearly rate paid at year end, interest on the current debt first, smaller last payment | Closed formula; monthly rates; constant Tilgung | Closed formula is a Kl. 9/10 bound (curriculum-sources). Fixed-rate tables are the spreadsheet-style approach; monthly rates would need 12× longer tables. Constant-Tilgung loans are not modelled (open item) |
| D61 | The plain-text formula fallback converts `{,}` before `\frac`, so `\frac{102{,}4}{100}` reads “(102,4)/100” | Avoid decimals inside fractions | Found by the Ch6 worksheet DOM test; KaTeX itself was never affected |
| D62 | Units `h`, `min`, `Tage` added to `UNITS` (inputs „8 h“, „8 Std“, „8 Stunden“, „7,5 min“, „40 Tage“). Units that are not answer units (km/h, cm, cm², m³) appear only in texts and headers | Strip any word after the number; no units in Ch2 | Dreisatz answers naturally carry these units; a wrong known unit („8 min“ for hours) is a real error worth naming (`unit_confusion`, D56). Specs without `unit` keep the strict behaviour (oracle test) |
| D63 | Questions may carry a read-only `promptTable` `{columns, rows}` (strings, may contain $…$), rendered as a real table (column headers, first column as row headers) under the prompt in practice and on the student sheet; not repeated on the answer key. The worksheet layout copies it only when present | Text lines „2 kg → 3,60 €“; LaTeX `array` | Judging a Wertetabelle needs a table; a data field keeps the UI generic (also useful for Ch7). Only-when-present keeps all earlier golden worksheets byte-identical (verified) |
| D64 | No drawn graphs in Ch2 until a diagram module exists. Family `graph_type` works with coordinates (points on a line through the origin) and with the shape of the point set described in words (line through O / line not through O / falling curve approaching the axes / rising curve getting steeper), decided from a value table | Draw SVG graphs now; drop graph tasks | Drawing graphs is a cross-chapter module (planned with geometry); the curriculum's “different representations” are still exercised via coordinates, tables and verbal descriptions |
| D65 | Ch2 structure: per skill one table template (fill + classify), one Dreisatz template (L2–L3 compute, L4 judge model and calculation: three statements, exactly one true), plus graph (prop) and decide (antiprop: L1 situation in words, L3 Dreisatz without stated type). New family `model_check` in both skills, `fill_table` in the antiproportional skill. Classify options at L2+ include a statement with the right verdict but the wrong reason („je mehr, desto mehr/weniger“, gleiche Zuwächse), which is graded wrong | One template per family; only verdicts without reasons | Catalog L4 asks for model plausibility; the reason options target the main misconceptions. Prompt says „Wähle die Aussage mit der richtigen Begründung“ so the grading is transparent |
| D66 | Numeric answers may carry `probability: true` (fraction/decimal only, never with `unit`): input may also be a percentage („37,5 %“, „37,5 Prozent“ = 0,375); a wrong value outside [0; 1] that is no listed distractor gets the feedback „Eine Wahrscheinlichkeit liegt immer zwischen 0 und 1“ (concept_confusion). Probabilities are not required in reduced form („6/16“ is correct) | Separate `percent` answer type; require reduced fractions | Schools accept all three representations; the value is what is graded. Generic engine flag, no Ch7-specific UI |
| D67 | Ch7 notation: sets with semicolons, E = {2; 4; 6} (comma is the decimal separator), empty set „{ }“, words in `\text{}`; the sample space is named „Ergebnismenge“ in words (no Ω/S symbol); sets are displayed in canonical order (numbers ascending, words in code-point order) so equal sets print identically; outcomes of repeated coin throws as letter strings (KZ); two dice as ordered pairs (rot; blau). Probabilities shown as reduced fractions, plus decimal and percent in the result line when they terminate | Commas in sets; Ω | Book notation not checked against LS7 pages (provisional, like D47) |
| D68 | Ch7 scope: Kenngrößen only from Kl. 5/6 (Min, Max, Spannweite, Median, Mittelwert; no Quartile/Boxplot); no Baumdiagramme or Pfadregeln (3.2.5(11), (12) have no LS7 section); two dice are counted in the 6 × 6 scheme of ordered pairs; counting with product rule, arrangements (≤ 5!) and ordered choices without repetition only; „performing experiments“ (3.2.5(6)) and the GFS „Simulation“ are not modelled (no runtime simulation) | Tree diagrams for two dice | Scope rule: no technique beyond the verified curriculum/TOC |
| D69 | Ch7 structure: data.analyze = stats (L1–L3) + judge (L4 multiselect of four statements, ≥ 1 true and ≥ 1 false); experiments = one template (L1 Ergebnismenge choice or event multiselect, L2 set choice, L3 und/oder/nicht, L4 reverse multiselect incl. equivalent descriptions); determine = compute (L1 sum from a table, L2 complement/missing entry), counting (L3), claims (L4, exactly one of three statements true); frequency = one template with four families (L1–L4); laplace = compute (L1–L3) + judge (L4). For choice tasks whose options are sets, the independent solver computes the set by predicates and returns the option whose displayed set equals it; conceptual L4 claims (coin, rain, six, lotto) are keyed by construction, numeric ones (two wheels) by BigInt cross-multiplication | Free text for „Ereignis formulieren“ | Free text is not auto-gradable (rule 5); the reverse direction tests the same competence |
| D70 | „Im Unterricht behandelt“ works on textbook **sections** (36 ids `chN.sM` from the TOC). A skill is offered only when **all** its sections are marked (`covered`); `partial` is shown but not offered. Switch off by default; turning it off keeps the marks. Stored in `progress.settings.coverage` (export/import/delete for free). Filter applies to Üben (options disabled with „noch nicht behandelt“, empty state), Wiederholen and the Start due counter (hidden skills mentioned, not silently dropped), Start chapter panel and worksheet topic selection; Fortschritt and saved worksheets are not filtered (history, reproducibility). Logic in `src/coverage.js`; the UI only asks `isSkillAvailable` / `partitionSkills` | Mark per chapter only; mark per skill; offer a skill when any section is covered; filter families inside a skill | Sections are what a student sees in the book and the class calendar. Multi-section skills (IV.2–3, VI.2–4) mix content of all sections in their templates, so „any section“ would show untaught content. Per-family filtering would need a section per family and template-level selection — possible later, not needed for correctness now |
| D71 | Mapping verification rule: a content-standard mapping is `verified` when the Klett Stoffverteilungsplan (S4) lists the standard for the skill's chapter **and** the skill's content matches the standard's wording (S3); a mapping S4 does not list for that chapter is removed. S4 is chapter-level, so „verified“ means „the book's chapter covers this standard and this skill exercises it“, not „section X teaches it“. Each chapter now stores S4's list (`chapter.curriculum.standards`); a test requires every 3.2.x mapping to be in it and lists the known gaps explicitly | Keep provisional until a section-level source exists | S4 is the publisher's own alignment for exactly this book edition; section-level alignment is not published |
| D72 | Applying D71: removed 3.2.4(3) from Ch II (S4 lists (1), (4) only) and 3.2.1(5) from Ch IV (S4 lists it for Ch I only; setting up equations is the process competence „Modellieren“ there). Moved 3.2.5(6) „Zufallsexperimente durchführen und auswerten“ from `experiments` to `frequency`, which evaluates given series (performing is not modelled, D68 — recorded in the mapping `note`). Loan → 3.2.1(4) verified with the note that the spreadsheet itself is not modelled. Process competence „2.1“ for `ch5.proof.isosceles` stays provisional (S4 names the area „Argumentieren und Beweisen“, not the number) | Keep the old mappings as provisional | Prefer fewer, correct mappings; notes keep partial coverage honest |
| D73 | Gaps found by S4, kept visible instead of patched: 3.2.3(10) Tangenten (listed for Ch III and Ch V) and 3.2.3(5) in Ch V have no skill yet. They are recorded in `test/coverage.test.js` and in PROGRESS.md for the geometry sessions; no skill was invented for them now | Add a planned skill now | Ch3/Ch5 are not modelled yet; the section that teaches tangents is not identified (S4 is chapter-level) |
| D74 | Adaptive logic is a pure engine module (`src/adaptive.js`) with all parameters in one frozen `ADAPTIVE_RULES`; the UI calls `recommendLevel`, `adaptiveStats`, `prerequisiteAdvice`, `scheduleReviewAdaptive` and shows the result. The old `masteryOf` / `scheduleReview` stay (legacy, still tested) but the UI no longer uses them | Change `progress.js` in place; put thresholds in the UI | Old tests and exports stay valid; one place to tune; logic-separation test keeps passing |
| D75 | Evidence per skill = `detail: [{l, o, d}]` (level, outcome clean/hinted/miss, date), last 24, written by `applyEvent` from events that now carry `level`. Outcomes are stored, scores are computed (`hintCredit` is tunable retroactively). Records without detail read their legacy `recent` as level-less evidence; `validateProgress` accepts older exports (defaults) and rejects malformed detail/box/diagnostics | Store scores; migrate old records on import | Raw facts survive a rule change; no data migration; old backups still import |
| D76 | „Sicher“ = ≥ 10 of the last 12 questions, mean score ≥ 0.8 **and** a proven level ≥ min(3, top level) (≥ 3 questions at that level or above with mean ≥ 0.75). Hints count half, the worked solution counts zero | Accuracy only (S3 rule) | Twelve easy questions must not read as mastery; „no mastery from one answer“ is a test |
| D77 | Start level: highest *supported* level (≥ 2 questions at/above it with mean ≥ 0.6), one higher after ≥ 4 questions at/above it with mean ≥ 0.8; one miss never lowers it. In-session: 2 clean in a row up, 2 misses in a row down, hinted neutral; items generated one at a time (`levelMode 'adaptive'`, `startLevel` stored in the session); the old ramp stays as „Gemischt, steigend“; „Automatisch (passt sich an)“ is the new default | Last-level heuristic; Elo/IRT; pre-planned levels | Stateless and explainable to a 12-year-old; deterministic for (seed, start level, answers); an Elo-style model would need calibration data we do not have |
| D78 | Spaced revision = Leitner boxes with ladder 1, 2, 4, 7, 14, 28 days; a box grows only when the topic was due (no climbing by practising twice a day), halves on a weak window, and is capped at 7 days without mastery | Fixed 1/3/7–28 rule; SM-2 ease factors | Fixes the S3 loophole (repeat sessions doubled the interval); SM-2 ease needs per-item grades we do not collect |
